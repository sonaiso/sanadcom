# الرخصة واستراتيجيّة البيع (2026-11-02) — معلن، يحتاج مراجعة قانونيّة

## الواقع في المستودع
- كلّ ما خارج `enterprise/` برخصة **AGPLv3** (موروثة من CISO Assistant Community).
- كلّ ما داخل `enterprise/` برخصة **intuitem التجاريّة**: لا يُستعمل ولا يُوزَّع بلا عقد مع intuitem.
- شيفرة المجتمع تستورد مرّةً واحدة من `enterprise_core` (`backend/core/management/commands/dump_permissions.py`) داخل `try` محروس؛ مسجَّلة في بوّابة العزل كاستثناء مؤقّت.

## ما تسمح به AGPLv3 (بإيجاز، ليس رأيًا قانونيًّا)
- بيع الاستضافة، والتشغيل، والدعم، والتدريب، والتكامل، والاستشارات: نعم.
- تعديل الشيفرة وتشغيلها كخدمة: نعم، بشرط إتاحة الشيفرة المعدَّلة لمستخدمي الخدمة عبر الشبكة.
- إغلاق الشيفرة: لا.

## الخيارات
1. **مفتوح بالكامل** (الحالة الراهنة): sanadcom كلّه AGPL؛ الإيراد من الاستضافة السياديّة والدعم والاعتماد عبر Silver Wolf. أبسط قانونيًّا، ويتوافق مع ادّعاء الشفافيّة بعد الحادثة.
2. **نواة مفتوحة + طبقة منفصلة:** الذكاء التفسيريّ (NABT + Mashru + النواة الدستوريّة) وحدة مستقلّة تتخاطب مع المنصّة عبر API فقط؛ يمكن ترخيصها برخصة أخرى إن كانت مستقلّة فعلًا (لا تستورد من شيفرة AGPL ولا تُربط بها في عمليّة واحدة). مشاريع NABT وMashru وAlghanem لها رخصها الخاصّة؛ يُراجع كلّ منها.
3. **عقد مع intuitem** لاستعمال `enterprise/`: فقط إن احتاج العميل ميزات المؤسّسة (SSO المتقدّم، التعدّد المؤسّسيّ).

## التوصية (معلن)
الخيار 1 الآن، مع تهيئة الخيار 2 بنيويًّا من الشريحة S5 (الربط عبر API لا عبر الاستيراد). القرار النهائيّ بعد رأي قانونيّ مكتوب.
